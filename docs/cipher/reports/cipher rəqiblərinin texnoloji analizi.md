# Rəqiblər brauzerə çəkilir, cipher user-mode-da qalib gələ bilər

cipher-in rəqibləri dörd düşərgəyə bölünür. Birincisi AI-native startaplardır: Harmonic, LayerX (indi Akamai), Prompt Security (indi SentinelOne), Lasso, Aim (indi Cato), WitnessAI, Nightfall. İkincisi klassik endpoint DLP-dir: Microsoft Purview, Forcepoint, Symantec, Digital Guardian, Trellix, Cyberhaven, Teramind, Endpoint Protector. Üçüncüsü enterprise brauzerlərdir: Island, Prisma Access Browser, Edge for Business, Chrome Enterprise Premium. Dördüncüsü SASE/SSE-dir: Netskope, Zscaler, Palo Alto, Cloudflare. Bu araşdırmanın əsas nəticəsi belədir: dörd düşərgənin hamısı eyni nöqtəyə, **brauzer qatına + lokal agent kanalına** gəlib çıxır. Symantec Chrome-u hook etməkdən imtina edib extension-a keçdi. Island və Palo Alto Chromium fork-larının yanında artıq extension da satırlar. SASE vendorları isə pinned desktop app-ları görə bilmədiklərini özləri etiraf edir və istifadəçini brauzerə yönləndirirlər. Deməli, cipher-in "extension + agent + gateway" dizaynı güzəşt deyil, bazarın getdiyi istiqamətdir. Rəqiblərin hamısı ML/LLM aşkarlamasını əsas üstünlük kimi təqdim edir, regex-only yolu isə heç kim feature kimi satmır. Amma Microsoft-un öz SIT modeli göstərir ki, sənayenin nüvəsi hələ də regex + checksum + açar söz + yaxınlıq + confidence-dir, yəni cipher bu nüvəni ML olmadan qura bilər. Kernel driver olmadan **hər kanalda müşahidə və xəbərdarlıq mümkündür**. **Real blok** isə yalnız tətbiqin özü əməkdaşlıq edəndə (MV3 extension, Chrome Content Analysis Connector) və ya gateway-də mümkündür. Ən böyük yeni fürsət Chrome-un açıq (BSD-3) Content Analysis SDK-sıdır: Chrome paste, upload və print məzmununu lokal agentə verir və onun verdiktini gözləyir. Ən böyük yeni risk macOS pasteboard privacy-dir: macOS 15.4-dən başlayaraq clipboard-un proqramla oxunması default olaraq istifadəçidən icazə istəyir, macOS 26 beta 4-də isə bunun MDM ilə əvvəlcədən təsdiq açarı yox idi. 2025–2026-da üç AI-native startap $180–350M-a platforma vendorlarına satılıb. Heç bir vendor açıq qiymət və ya self-serve sınaq vermir, cipher-in fərqlənəcəyi boşluq da elə buradadır.

## Dörd düşərgə, yeddi AI-native startap və üç alış: rəqiblər xəritəsi

Aşağıdakı cədvəllər forma faktorunu, OS və brauzerə necə qoşulduqlarını, məlum stack-i, aşkarlama metodunu, hərəkətləri və statusu bir yerə toplayır. **[ML]** işarəsi aşkarlamanın ML, SLM və ya LLM-ə söykəndiyini göstərir, yəni cipher-in bilərəkdən etmədiyi şeyi. "Açıqlanmayıb" o deməkdir ki, ictimai mənbədə tapılmadı. Texniki detalların çoxu vendor marketinqindən və ya rəqib müqayisələrindən gəlir. Heç bir vendor üçün müstəqil reverse engineering, Chrome Web Store icazə siyahısı və ya FP/FN benchmark tapılmadı.

## Hamı eyni üç hissəni qurur: extension, lokal agent kanalı və bulud konsolu

### OS-a necə bağlanırlar

macOS-da mənzərə bütün vendorlarda eynidir və yaxşı sənədləşdirilib. Fayl və proses hadisələri üçün **Endpoint Security system extension**, trafik üçün **Network Extension** (content filter və ya transparent proxy) istifadə olunur. Daemon-lara **Full Disk Access**, UI konteksti və clipboard üçün **Accessibility** verilir, hamısı MDM profilləri ilə əvvəlcədən təsdiqlənir. Purview `accessibility`, `fulldisk`, `netfilter` və `sysext` mobileconfig-lərini birlikdə göndərir ([Learn](https://learn.microsoft.com/en-us/purview/device-onboarding-offboarding-macos-any-mdm)). Forcepoint FDA-nı dörd prosesə verir, o cümlədən `ESDaemonBundle.app`-a ([Forcepoint](https://help.forcepoint.com/F1E/en-us/v26/ep_install/D19DA675-72CD-49BD-A5E6-529795064E80.html)). Symantec `edpa` və `SEHA.app` üçün FDA tələb edir ([KB 198350](https://knowledge.broadcom.com/external/article/198350/install-requirements-for-dlp-mac-agent.html)). MDM-lə əvvəlcədən təsdiq edilməsə, FortiDLP-də sysext və network extension sorğuları **hər açılışda yenidən çıxır** ([Fortinet](https://community.fortinet.com/fortidlp-66/technical-tip-deploying-macos-fortidlp-agents-via-jamf-187496)). Yəni MDM payload-u məhsulun ayrılmaz hissəsidir. Vacib bir nüans da var: ES və Network Extension kernel extension deyil, **user-space system extension**-dır. Onları məhdudlaşdıran şey kernel deyil, Apple-ın verdiyi entitlement-dir. ES client entitlement-i olmadan `es_new_client` `ERR_NOT_ENTITLED` qaytarır ([Apple](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.endpoint-security.client)).

Windows-da vendorlar daxili quruluşu demək olar ki, açıqlamır. Digital Guardian "kernel level" görünürlük və "application layer injection" deyir. Cyberhaven kernel, fayl sistemi və şəbəkə API-ləri üçün mühəndis axtarır. Hansı driver fayllarından istifadə olunduğu heç bir mənbədə göstərilmir, ona görə minifilter və WFP callout-lar **ehtimaldır, fakt deyil**. Təsdiqlənmiş olan isə user-mode **DLL injection və API hooking**-dir. Symantec-in "Application Monitoring"-i işə düşəndə agent "hər tətbiqə hook etməyə çalışır" və bəzi app-lar "pis işləyir", ona görə istisna siyahıları yaranır ([KB 170410](https://knowledge.broadcom.com/external/article/170410/)). Broadcom performans sıçrayışlarını da ayrıca sənədləşdirir. SASE vendorlarında agent sadəcə yönləndirici client-dir: Zscaler-də Windows-da NDIS LWF və WFP driver-ləri, macOS-da NE (üçüncü tərəf mənbəyi). Məzmun yoxlaması isə buludda aparılır ([dope.security, rəqib](https://dope.security/post/netskope-client-2026)). Microsoft-un üstünlüyü strukturdur: DLP Windows-la birlikdə gələn Defender komponentlərinin üstündə qurulub və bunu heç bir üçüncü tərəf təkrarlaya bilməz.

### Brauzerə necə bağlanırlar

Ən aydın trend budur: **brauzeri hook etmək bitib, MV3 extension + lokal agent kanalı standart olub**. Symantec 15.8-də Chrome hooking-dən extension-a keçdi və indi Content Analysis Connector-ları tövsiyə edir ([KB 162676](https://knowledge.broadcom.com/external/article/162676/incidents-generated-by-endpoint-prevent.html)). Purview-un Chrome extension-u MV3-dədir və agentlə native messaging ilə danışır. Admin `NativeMessageBlocklist` qoyubsa, extension ID-si ayrıca allowlist-ə əlavə edilməlidir ([Learn](https://learn.microsoft.com/en-us/purview/dlp-chrome-get-started)). Forcepoint isə localhost socket istifadə edir. v26 buraxılış qeydlərində `wepsvc`-in 127.0.0.1 əvəzinə 0.0.0.0:55299-a bağlanması xətası düzəldilib ([Forcepoint](https://help.forcepoint.com/F1E/en-us/v26/ep_release_notes/7F272842-E89A-4202-8CA9-2E8ED83B4581.html)). cipher üçün dərs aydındır: lokal kanal ya native messaging olmalıdır, ya da loopback-a bağlanmış, autentifikasiyalı socket. AI-native vendorların extension-ları DOM hadisələrini tutur: typing, paste, click, upload (Prompt) və ya paste anında xəbərdarlıq (Harmonic). LayerX-in "Man in the Prompt" araşdırması göstərdi ki, **heç bir xüsusi icazəsi olmayan extension** ChatGPT/Gemini prompt-unu DOM üzərindən oxuya və dəyişə bilir ([CyberInsider](https://cyberinsider.com/the-top-ai-tools-exposed-to-man%e2%80%91in%e2%80%91the%e2%80%91prompt-browser-extension-attack/)). Bu həm cipher-in texnikasının işlədiyini təsdiqləyir, həm də qorunmalı olduğu təhdidi göstərir.

Enterprise brauzerlər fərqli yol seçib. Island və Talon/PAB dərin nəzarət üçün **C++ Chromium fork**-una mərc etdilər: screenshot, print, proseslər arası clipboard, watermark. Sonra istifadəçilər brauzer dəyişmək istəmədiyi üçün extension da əlavə etdilər. Edge for Business isə **yazılan prompt-u** native yoxlayır, Chrome Connector-ları isə yalnız paste, drag-drop və faylları görür. Microsoft "istifadəçi başqa brauzerə keçir" probleminə texniki həll tapmayıb, sadəcə siyasətlə həll edir: Intune avtomatik olaraq qorunmayan brauzerləri bloklayan siyasətlər yaradır və **Firefox tamamilə bloklanır** ([Learn](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-dlp-purview-configuration)).

Şəbəkə vendorlarının AI payload-larını "başa düşməsi" hər app üçün yazılmış parser-lərə əsaslanır. Cloudflare HTTPS sorğularını ChatGPT `SendPrompt` kimi əməliyyatlara uyğunlaşdırır, ChatGPT-nin `text/event-stream` cavab parçalarını tam cavaba yığır və prompt, cavab və conversation ID-ni çıxarır. Bu yalnız web versiyalarında, dörd app üçün işləyir: Gemini, ChatGPT, Claude, Perplexity ([Cloudflare](https://blog.cloudflare.com/ai-prompt-protection/)). Palo Alto-da kataloq 600+ app-dır, amma DLP yalnız ~30 app-ı parse edir. Bu fərq göstərir ki, dərin yoxlama baha başa gəlir və app-lar private API-lərini dəyişdikcə parser-lər sınır. Desktop AI app-lar isə hamının etiraf etdiyi zəif yerdir. Netskope-a aid FAQ ChatGPT macOS app-ının pinning səbəbindən "daha çətin" olduğunu deyir və istifadəçiləri brauzerə yönləndirməyi məsləhət görür (ikinci dərəcəli xülasə, **təsdiqlənməyib**).

### Həssas məlumatı necə tapırlar

Marketinqdə hamı ML-dən danışır. Harmonic SLM, Prompt "LLM-based", WitnessAI "intent, keyword deyil", Nightfall 125M parametrli transformer, Cloudflare Llama3-70B deyir. Heç bir vendor regex-only yanaşmanı feature kimi təqdim etmir. Amma nüvəyə baxanda başqa mənzərə görünür. Microsoft custom SIT-ləri "pattern", "keyword evidence", "character proximity" və "confidence level" ilə təyin edir. Primary element "checksum ilə və ya checksum-suz regex, keyword siyahısı, lüğət və ya funksiya" ola bilər ([Learn EDM](https://learn.microsoft.com/en-us/purview/sit-learn-about-exact-data-match-based-sits)). Microsoft EDM-də müştəri dataları duzla hash-lənir, "yalnız hash-lər yüklənir", 100 milyona qədər sətir dəstəklənir və uyğunlaşma əvvəlcə pattern SIT-in tapdığı primary element üzərindən başlayır. Google CEP də "regex-ə uyğundur", "söz siyahısından söz" və AND/OR/NOT kombinasiyaları təklif edir. ML-in əlavə etdiyi şey trainable classifier-lər, named entity tanıma və adaptive risk scoring-dir. cipher bunları ML olmadan təkrarlaya bilməz və bunu açıq demək daha düzgündür.

ML-in zəif tərəfi də sənədləşdirilib. Cloudflare özü yazır ki, Llama3-70B prompt injection-a həssasdır. Onların nümunəsində prompt "bu ev ünvanı PII deyil" deyərək modeli aldadır. Hər model üçün P90 <1 s gecikmə hədəfi var ([Cloudflare](https://blog.cloudflare.com/ai-prompt-protection/)). Nightfall-un dəqiqlik rəqəmləri isə öz səhifələri arasında ziddiyyətlidir: bir yerdə "95% precision", başqa yerdə "95% accuracy". Heç bir vendor üçün müstəqil FP/FN benchmark yoxdur. Bu boşluq cipher üçün həm müdafiə xəttidir, həm də hücum imkanı. cipher öz FP nisbətini ictimai korpusda ölçüb dərc edə bilər, rəqiblərin heç biri bunu etmir.

## User-mode-da müşahidə hər yerdə mümkündür, blok yalnız əməkdaşlıq edən nöqtələrdə

Aşağıdakı matris qeydlərdəki rəsmi platforma sənədlərinə əsaslanır. Bəzi xanalarda vendor sübutu yox, mühəndis nəticəsi var, onlar "(ehtimal)" və ya "(yoxlanılmalı)" kimi işarələnib. Hərflər belə oxunur: **M** müşahidə, **X** xəbərdarlıq/coach, **B** real blok. ✓ mümkün, ◐ məhdud və ya şərtli, ✗ user-mode-da mümkün deyil.

Matrisin əsas nəticəsi budur: **cipher v1-də "block" vədi yalnız üç yerdə dürüstdür**: brauzer extension-u, Chrome Connector və gateway. OS clipboard sensoru "warn + audit" siqnalıdır. Windows-da bu siqnal güclüdür, Linux X11 və KDE-də qənaətbəxşdir, macOS-da isə pasteboard privacy səbəbindən məhduddur.

**Windows-da** session-0 problemi rəsmi sənədlərlə təsdiqlənir. Xidmət kontekstindəki hər prosesin session ID-si 0-dır. `WTSQueryUserToken` LocalSystem və `SE_TCB_NAME` tələb edir ([Learn](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtsqueryusertoken)). Clipboard və WinEvent hook-ları desktop səviyyəsində işləyir və mesaj dövrü tələb edir. Ona görə SYSTEM xidməti hər interaktiv sessiyada `CreateProcessAsUser` ilə istifadəçi sensoru açmalıdır və onlar ACL-li named pipe üzərindən danışmalıdır. AMSI DLP üçün yararsızdır: yalnız host-un özünün göndərdiyi script və makroları görür, üstəlik cipher-i AV komponenti kimi göstərir ([Learn](https://learn.microsoft.com/en-us/windows/win32/amsi/antimalware-scan-interface-portal)). Tamper qorunması üçün dürüst ifadə "qarşısını alma" deyil, "çəkindirmə + dayandırılma telemetriyası" olmalıdır. Qorunan (PPL) xidmət üçün ELAM driver lazımdır, Microsoft Virus Initiative üzvlüyü də, amma bu ikinci şərt yoxlanılmamış ön bilikdir.

**macOS-da** user-mode agent LaunchDaemon (root) + LaunchAgent (istifadəçi GUI sessiyası) cütlüyündən ibarətdir. Bunun yanında Developer ID imzası, Hardened Runtime və `notarytool` ilə notarizasiya məcburidir ([Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)). ES və NE entitlement-ləri v1 üçün ağırdır, amma texniki olaraq "kernel driver yoxdur" şərtini pozmur. **Linux-da** Ubuntu və RHEL default olaraq GNOME Wayland-la gəlir, GNOME Mutter isə data-control protokolunu dəstəkləmir ([Mutter #524](https://gitlab.gnome.org/GNOME/mutter/-/issues/524)). Ona görə Linux clipboard əhatəsi hissəvi olacaq və orada əsas yük extension-un üzərinə düşür. Distro-ların çoxunda unprivileged eBPF söndürülüb ([kernel.org](https://www.kernel.org/doc/html/latest/admin-guide/sysctl/kernel.html)), bu səbəbdən eBPF MVP-yə daxil edilməməlidir.

**Brauzerdə** bir neçə texniki məhdudiyyət dizaynı müəyyən edir. MV3-də WASM yalnız extension_pages CSP-də `'wasm-unsafe-eval'` olduqda işləyir, `'unsafe-eval'` isə quraşdırma xətası verir ([Chrome](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy)). Native messaging content script-lərdə **mövcud deyil**. Host-dan extension-a mesaj 1 MB, əks istiqamətdə 64 MiB ilə məhdudlaşır ([Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)). Paste-i bloklamaq qərarı sinxron olmalıdır, ona görə engine service worker-ə gedib-gəlmədən birbaşa content script-də işləməlidir. Admin siyasəti `chrome.storage.managed` ilə gəlir ([Chrome](https://developer.chrome.com/docs/extensions/reference/api/storage)). `installation_mode: force_installed` olan extension-u istifadəçi silə bilməz ([Google](https://support.google.com/chrome/a/answer/9867568?hl=en)). Firefox host manifest-ində `allowed_origins` əvəzinə `allowed_extensions` istifadə edir və managed storage-ni ayrıca manifest-dən oxuyur ([MDN](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Native_manifests)). Safari force-install-u bütün sənayenin ümumi problemidir: Nightfall-da Safari yalnız əl ilə quraşdırılır.

## Chrome Content Analysis SDK: Symantec və Trellix-in istifadə etdiyi kanal cipher üçün də açıqdır

Google-un rəsmi, açıq mənbəli (**BSD-3-Clause**) SDK-sı lokal DLP agentinə Chrome-un Content Analysis Connector-u üçün "service provider" olmaq imkanı verir ([GitHub](https://github.com/chromium/content_analysis_sdk)). Repo C++, CMake 3.23+ və Protobuf 3.18+ ilə qurulub. Son commit 2026-08-11-ə aiddir, yəni layihə aktiv saxlanılır. Mexanizm belə işləyir. Admin `OnBulkDataEntryEnterpriseConnector` (paste və drag-drop), `OnFileAttachedEnterpriseConnector` (upload) və `OnPrintEnterpriseConnector` siyasətlərində provayderi `local_system_agent` və ya `local_user_agent` kimi təyin edir. Bundan sonra Chrome məzmunu agentə göndərir və agentin verdiktini gözləyir. Paste üçün `text_content`, fayl üçün `file_path`, print üçün shared-memory handle ötürülür, yanında URL, fayl adı, SHA-256, tab başlığı və daxil olmuş email gedir ([analysis.proto](https://raw.githubusercontent.com/chromium/content_analysis_sdk/main/proto/content_analysis/sdk/analysis.proto)). Agent hər tag üçün `REPORT_ONLY`, `WARN` və ya `BLOCK` qaytarır. Chrome özü native block və warn UI-ni göstərir, sonra `final_action` ilə təsdiq (acknowledgement) göndərir. Cavab gecikəndə bu təsdiqin statusu `TOO_LATE` olur. Bu kanalın extension-dan üstünlüyü odur ki, onu brauzer özü tətbiq edir: istifadəçi extension-u söndürə bilmir, DOM selector-ları sınmır.

Siyasət sahələri cipher-in konsol dizaynı üçün hazır şablondur ([YAML](https://raw.githubusercontent.com/chromium/chromium/main/components/policy/resources/templates/policy_definitions/Miscellaneous/OnBulkDataEntryEnterpriseConnector.yaml)): tag-lı `enable`/`disable` `url_list`-ləri, `block_until_verdict`, xəta halında fail-open və ya fail-closed seçimi (`default_action`), **default 100 bayt** olan `minimum_data_size`, `require_justification_tags`, ≤200 simvolluq `custom_messages` + `learn_more_url`, agentin kimliyini bağlamaq üçün hər OS üzrə `verification` açarları. `service_provider` enum-u `google`, `local_user_agent`, `local_system_agent`, `brcm_chrm_cas` və `trellix` dəyərlərini qəbul edir. Windows nəqliyyatı mənbə kodunda təsdiqlənib: **named pipe**. Sistem rejimində pipe `ProtectedPrefix\Administrators\` altında yaradılır, ona görə admin olmayan proses agentin yerinə keçə bilmir. `user_specific` rejimində pipe adına SID əlavə olunur. Pipe-lar `PIPE_REJECT_REMOTE_CLIENTS` və overlapped I/O ilə açılır ([utils_win.cc](https://github.com/chromium/content_analysis_sdk/blob/main/common/utils_win.cc)). Bu birbaşa cipher-in iki prosesli arxitekturasına uyğun gəlir: pipe-ı SYSTEM səviyyəli `cipher-service` yaradır. Rust-da həyata keçirməyin iki yolu var: `liblcasdk`-nı FFI ilə linkləmək, ya da proto2 mesajlarını `prost` ilə yenidən yazmaq və pipe framing-i özün qurmaq. İkinci yol tək-binary, C++-sız agent ideyasına daha uyğundur. Broadcom-un artıq bu kanalı tövsiyə etməsi onun sənaye standartına çevrildiyini göstərir.

Məhdudiyyətlər də ciddidir. Connector **yazılan mətni görmür**: siyasət yalnız clipboard-dan və ya drag-drop ilə daxil edilən məlumatda işə düşür. Deməli, extension yenə lazımdır. Açıq SDK-da macOS və Linux yolları **stub-dır**: `Agent::Create` `ERR_UNEXPECTED` qaytarır ([agent_mac.cc](https://github.com/chromium/content_analysis_sdk/blob/main/agent/src/agent_mac.cc)). Halbuki Chromium build flag-ı lokal analizi Windows, macOS və Linux-da aktiv edir ([buildflags.gni](https://raw.githubusercontent.com/chromium/chromium/main/components/enterprise/buildflags/buildflags.gni)). Siyasətlər `cloud_only`-dir, yəni GPO və ya registry ilə deyil, Google Admin console ilə verilir. Cihazlar Chrome Enterprise Core-a qoşulmalıdır, Google-un sənədində isə vendor kimi yalnız Broadcom Symantec və Trellix göstərilir ([Google](https://support.google.com/chrome/a/answer/13876556?hl=en)).

## Hazır açıq mənbə hissələri: MIT/BSD/Apache-ni götür, AGPL/GPL-i yalnız oxu

Engine üçün lazım olan hissələrin hamısı permissive lisenziyalarla mövcuddur və 2026-da aktiv saxlanılır. Bazarda yetkin, geniş istifadə olunan Rust DLP layihəsi yoxdur. Mövcud gənc crate-lər dizayn üçün istinad ola bilər, amma asılılıq kimi götürülməməlidir.

| Komponent | Lisenziya | cipher-də istifadəsi | Hökm |

## Risklər: macOS pasteboard, Wayland və "regex köhnədir" hücumu

**macOS pasteboard privacy ən böyük texniki riskdir.** macOS 15.4-də `NSPasteboard.accessBehavior` əlavə olundu. General pasteboard üçün default davranış "proqramla oxunanda soruş"-dur. `alwaysDeny` isə istifadəçinin özünün başlatdığı paste-dən başqa hər şeyi səssizcə rədd edir ([Apple](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum)). Yeni `detect` metodları sorğu açmadan pasteboard-da hansı tiplərin olduğunu deyir, amma məzmunu vermir ([Michael Tsai](https://mjtsai.com/blog/2025/05/12/pasteboard-privacy-preview-in-macos-15-4)). Bir DLP vendoru İyul 2025-də Apple forumunda yazdı ki, oxuma "dərhal sorğu açdı". macOS 26 beta 4-də Device Management-də, o cümlədən PPPC-də "Paste from Other Apps" açarı yox idi. Apple DTS enhancement request (FB19085787) yazmağı məsləhət gördü ([Apple Forums](https://developer.apple.com/forums/thread/794560)). macOS 26 final-da bu məhdudiyyətin tətbiq olunub-olunmadığı və sonrakı 26.x versiyasında MDM açarı əlavə edilib-edilmədiyi **təsdiqlənməyib**, bunu ən yüksək prioritetlə real cihazda yoxlamaq lazımdır. Praktik nəticə: macOS-da enforcement-i Apple-ın məhdudlaşdırmadığı kanallara keçirmək lazımdır, yəni extension, Chrome connector və gateway. Clipboard sensoru isə istifadəçi "Always Allow" seçdiyi cihazlarda əlavə siqnal olaraq qalır.

**Linux Wayland** problemi məlumdur, amma indi konkret sərhədləri var. Data-control protokolunu KWin, Sway və Labwc kimi wlroots compositor-ları, Niri, Hyprland və Wayfire dəstəkləyir, sandbox-larda isə bu protokol olmaya bilər ([Vim docs](https://vim-jp.org/vimdoc-en/wayland.html)). GNOME isə dəstəkləmir. GNOME Wayland üçün iki seçim qalır: ya GNOME Shell extension yazmaq, ya da clipboard əhatəsindən imtina etmək. Linux-un sonuncu prioritet olması düzgün qərardır.

**Rəqiblərin regex FP nisbətinə hücumu** qaçılmazdır. Nightfall "regex-dən 85%-ə qədər yaxşı" deyir. Harmonic özünü açıq şəkildə pattern-matching DLP-yə qarşı qoyur. WitnessAI "keyword və ya pattern deyil, niyyət" deyir. Bu hücumun üç cavabı var. Birincisi, deterministiklik və izah oluna bilmə: eyni giriş həmişə eyni nəticəni verir və hər qərarın arxasında konkret qayda ID-si dayanır. İkincisi, prompt injection-a toxunulmazlıq: Cloudflare-in öz etirafı buna sübutdur. Üçüncüsü, gecikmə: rəqiblərin <200 ms və ~1 s rəqəmlərinə qarşı mikrosaniyələr. Amma bu cavabların işləməsi üçün FP həqiqətən aşağı olmalıdır. Zəif evristikalar (`\d{7,12}`, Title-Case ad) heç vaxt `block` səviyyəsinə qalxmamalıdır. FP ictimai korpusda ölçülüb dərc edilməlidir. EDM və sənəd barmaq izi kontekst tələb edən hallarda ML-in əvəzini qismən verməlidir. Harmonic-in nümunəsi, yəni "funksiyanı izah et" ilə "proprietary kodu yapışdır" arasındakı fərq, regex-in zəif yeridir. Mənbə kodu üçün sintaksis balı + şirkət repo-larının shingle hash-ləri bu boşluğu qismən doldurur.

Digər risklər də nəzərə alınmalıdır. **DOM və private API dəyişiklikləri** sayt adapterlərini sındırır. Palo Alto-nun 600-ə 30 nisbəti bunun nə qədər baha başa gəldiyini göstərir. **Bypass yolları** da var: incognito pəncərəsi default olaraq extension yükləmir ([KB 162676](https://knowledge.broadcom.com/external/article/162676/incidents-generated-by-endpoint-prevent.html)), istifadəçi qorunmayan brauzerə və ya desktop app-a keçə bilər, admin hüquqlu istifadəçi user-mode xidməti dayandıra bilər. **Chrome connector-un partnyor allowlist-i** ehtimalı var. **WASM-ın content script-də ciddi səhifə CSP-si altında işləməsi** (məsələn chatgpt.com-da) test edilməyib. **MV3 service worker-i** boş qalanda dayandırılır (ehtimal ~30 s), ona görə native port yenidən qoşula bilən olmalıdır. Presidio pattern-lərinin bir hissəsi lookaround istifadə edə bilər və onlar Rust `regex`-ə birbaşa köçmür.

## Nəticə

Bu araşdırma cipher-in əsas texniki sualını dəyişir. Sual artıq "kernel driver olmadan rəqiblərlə yarışmaq olarmı?" deyil. Sual "blok vədini hansı nöqtələrdə dürüst verə bilərik?" olub. Cavab dəqiqdir: extension, Chrome connector və gateway blok edir, OS sensorları isə xəbərdarlıq edib audit yazır. Bu bölgü məhsulun marketinqinə və siyasət UI-nə birbaşa daxil olmalıdır. Konsol hər kanal üçün hansı hərəkətin mümkün olduğunu göstərməlidir, macOS clipboard üçün isə `block` seçimi ümumiyyətlə təklif edilməməlidir. Chrome connector bütün bu xəritədə dəyəri ən yüksək, qeyri-müəyyənliyi də ən böyük olan elementdir. Partnyor allowlist-i və macOS/Linux nəqliyyatı ilə bağlı suallar bir həftəlik prototiplə cavablandırılmalıdır, Faza 2-nin Windows planı da bu nəticədən asılıdır.

Strateji baxımdan konsolidasiya dalğası ikitərəfli siqnaldır. Alıcıların çoxu AI-DLP-ni EDR, SASE və ya CDN suite-inin əlavəsi kimi alacaq. Eyni dalğa isə SASE-si olmayan, buludda prompt emalı istəməyən və ya yerli tənzimləmə tələblərinə tabe olan müştəriləri xidmətsiz qoyur. cipher-in deterministik, cihazda işləyən, açıq qiymətli və Azərbaycan detektorları ilə gələn modeli məhz bu seqment üçündür. Bu seqmentdə uğur ML-ə qarşı ideoloji mübahisədən yox, ölçülüb dərc edilmiş aşağı FP nisbətindən asılı olacaq.
